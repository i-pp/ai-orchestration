# Technical review

Compare each material claim with primary evidence. Separate observed output, user-reported outcome, hypothesis, opinion and an unexecuted illustration. Verify commands, numeric units, attribution, conditions and limits. A saved PASS is finite evidence, not a general proof or current rerun.

Inspect code and quoted sources independently of prose lint. Preserve original evidence; keep private fixtures, raw logs, secrets and real host paths outside article Git. Explain why each important failure occurs and what the changed code actually fixes. Keep a manual control distinct from AI success and code correctness distinct from response-format compliance.

Report checked sources and hashes, checks not run and remaining uncertainty. A Technical Reviewer may establish factual consistency, not readability or publication approval. Classify material technical errors, clear falsehoods and security/privacy exposure as BLOCKER. A style warning alone is MINOR unless a reviewer gives a concrete stronger impact.
