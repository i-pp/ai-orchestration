## Transferable review decisions

| Before → after | Evaluation question | Boundary |
| --- | --- | --- |
| Dense audit-led context → early purpose, goal, actual result and diagnostics | Can a busy reader decide whether this addresses their problem and choose a next action from the opening? | Keep the tested scope; do not turn inference completion into numerical correctness. |
| Collection-order detail → the contradiction “IRON runs, SDK inference fails” and investigation of the loaded library | Does each observation explain the next diagnostic choice? | Do not invent discovery chronology or a unique cause when version, plugin and environment changed together. |
| Formal qualification in many paragraphs → short, connected engineering prose | Can readers follow the reasoning without a repeated audit disclaimer? | Keep material limits at the affected claim; consolidate repeated detail in evidence/limitations. Natural first person needs sourced acts, not invented emotions or timing. |
| Environment record → diagnostic commands and a historical launcher | What prerequisites, expected output and failure interpretation make the command useful? | The launcher assumes SDK extraction, dependencies and a built app. This is Troubleshooting/Working Configuration, not a complete Quick Start. |
| Exhaustive detail → symptoms mapped to checks | Can the reader do or decide something specific after reading? | A symptom table is useful navigation, not evidence that a new host was tested. Avoid mandatory duplicate introductions/conclusions. |

For Quick Start classification, apply the workflow supplement: defined starting environment, dependencies/acquisition, setup/configuration/build, execution, success criteria, relevant recovery and limits. Otherwise choose Troubleshooting, Minimal Reproduction, Working Configuration or Proposed Procedure. Label original execution, reconstructed commands, static inspection and proposals separately. Do not execute article commands during editorial loading.

Writer, Editor and Technical Reviewer remain existing assignments. The Editor supplies an explicit reader-value/voice judgment; the separate Technical Reviewer validates evidence and reproducibility. Accurate but report-like prose is not an editorial pass. Record substantive rejection even if the mechanical handoff validator accepts the record; the validator does not read prose or certify reviewer honesty. Keep the two-cycle limit and non-blocking minor issues.

## Open findings on this example; originals unchanged

- **Evidence attribution (BLOCKER for publication).** Before line 119 says the memcpy `80.19 GB/s`/`1849 µs`/`PASS!` came from an assistant search fragment and the original terminal attachment was not recovered. After lines 311–322 describe terminal output and soften the gap to no fresh measurement. Do not promote a search fragment to a recovered execution record. Obtain the primary log or propose an accurately attributed revision separately.
- **Shape semantics (technical finding).** Before distinguishes symbolic metadata `[batch_size,3,32,32]`/`[batch_size,10]` from runtime `batch=1`; after lines 424–429 presents `[1,3,32,32]`/`[1,10]` as model shape. Verify the underlying model metadata and execution before proposing wording; a concrete execution shape does not establish a fixed model dimension.
- **Disclosure (hold under the explicit user requirement).** Before has a visible opening ChatGPT disclosure and `chatgpt` topic; after has neither. The new engineering standard does not cancel the earlier disclosure instruction. Under v2 propose a short visible notice after the reader-first opening or in an endnote, and a valid topic separately; do not silently add them to, or remove them from, the user's sample.
- **Later hash update (needs source reconciliation).** After line 650 says some SDK archive hashes remain unavailable. The current task reports that five inputs were subsequently fixed by hash. Check the dated manifest and which inputs it covers before proposing updated wording. Five fixed inputs do not establish a clean install or retroactively identify unrecovered historical archives. The precise later manifest is not loaded by this example bundle.
- **Reproducibility wording (MAJOR review candidate).** After line 579 says the successful configuration was left in a reproducible form, while new-host reconstruction remains unverified. Prefer the narrower historical working-configuration claim in a proposed revision unless independent reproduction evidence exists.
- **Voice provenance (review candidate).** A phrase such as “さっきまで” implies timing and remembered experience. Use the user's example to learn pacing, not to invent a thought, motive or sequence for another article.
